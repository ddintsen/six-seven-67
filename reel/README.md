# Showreel

A 68-second film of 67 made from the site's own parts: the glass-cube mark, the night forest with the balance, the market list, the real ticket, review, confirmation and claimed position, the four-calls plot, the realm's source, the type and the colours. 1920 × 1080, 30 fps, H.264 with an original synthesized track. Version 2 (12 October, evening) added the two interface shots and a new score; version 1 (60 s) is in the git history and, as a file, in `_to_delete/reel-v1/` on the owner's computer. The script and the shot list are in `docs/reel/SCRIPT.md`, the references in `docs/reel/REFERENCES.md`. Finished files go to `previews/reel/`.

| File | What it does |
| --- | --- |
| `timeline.ts` | The clock (120 BPM: beat 0.5 s, sixteenth 0.125 s), the scenes, and every cue: cube landings, price changes, the four call windows, code checks. Version 2's two interface inserts and `clock()`/`film()`, which map film time to the first cut's 60-second clock, so its 3D is reused |
| `world.ts` | The three 3D sets as pure functions of a state: the mark in glass cubes, the forest with the balance (kept in step with `src/landing/forestScene.ts`), the floating plot (kept in step with `src/landing/storyScene.ts`) |
| `overlay.ts` | The type: masked line reveals, the price odometer, the market list, code highlights, the ™; `createInserts` places the real screens of the two interface shots, with a press light and cuts on the beat |
| `ui.spec.ts`, `pw.ui.config.ts`, `ui/` | Captures the real screens from the running app through MockChain at 2× and 3× (`npx playwright test -c reel/pw.ui.config.ts`): ticket, review, confirmation, position before and after the claim, the claim's status line; `ui/frames.json` holds each screen's size and the rectangle of the pressed control |
| `main.ts` | The state of every set at time t, cameras, and `window.__reel.seek(t)` |
| `render.mjs` | Records frames through Playwright into ffmpeg; `stills` for quick checks, `video` for layers, `cues` for the score |
| `music.py` | The score, synthesized from `cues.json` (numpy, scipy), normalized to −14 LUFS with a true-peak ceiling. Version 2: F minor, a night-garage groove, plucked bars for the cubes, a sung chord hook |
| `build.sh` | The whole build: sound, 3D layer in resumable segments, type layer, composite with sound, poster; `splice` builds version 2's 3D from the first cut's segments plus a fresh four-calls segment |
| `cues.json` | Generated by `node reel/render.mjs cues`; read by `music.py` |

## Build

```sh
npm run dev                                   # serves the reel at http://127.0.0.1:6767/reel/index.html
bash reel/build.sh all /tmp/67-reel           # sound, 3d, type, mux; or run one stage: sound | 3d | splice | type | mux
V1_3D=/tmp/67-reel/3d bash reel/build.sh splice /tmp/67-reel-v2   # version 2's 3D from the first cut's segments
```

In the Linux cloud container the 3D layer uses software WebGL: about 4.5 s a frame for the forest and 0.9 s for the plot, about an hour in all; the type layer takes about 4 minutes, the mux 3. With a GPU, drop `--use-gl=swiftshader` from `render.mjs` and it takes minutes. The type layer and the mux take a few minutes, so text and timing can change without redrawing the 3D, as long as nothing in `world.ts` or the camera code in `main.ts` changes.

Quick looks: `node reel/render.mjs stills 4,20,37 --scale 0.5` writes half-size PNGs; `?t=20` on the page URL opens the reel at a moment.

**Do not edit files under `reel/` while a render runs**: the dev server reloads the page and the frames break.

## Changing it

- **Text**: `overlay.ts`. Lines are broken by meaning, sentence case, on the left axis (128 px).
- **Timing**: `timeline.ts`. Keep cuts on bar lines (every 2 s) and cubes on sixteenths; the score follows `cues.json` on the next `sound` stage. Inserts are whole bars; a new insert needs only the type layer and a splice, not new 3D.
- **Interface shots**: recapture with `reel/ui.spec.ts` after the app changes, then rebuild type and mux.
- **Music**: `music.py`. Chords per bar in `CHORDS`, bell notes per cue kind. A licensed or commissioned track can replace it; then re-time to its beat grid.
- **Another format** (9:16 or 1:1 for social): re-compose, do not crop: new cameras in `main.ts`, a new stage size in `reel.css`, then rebuild 3d and type.
